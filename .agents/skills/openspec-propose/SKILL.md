Локализованная адаптация skills, созданных `openspec init --tools codex` версии 1.17.0.
Работай на русском языке, соблюдай AGENTS.md и контекст openspec/config.yaml.
Команды, JSON-поля, идентификаторы артефактов и служебные маркеры не переводи.

Перед записью выполни `openspec list --json`, проверь `root`. Если корня нет,
не создавай его побочно: при явном запросе OpenSpec уточни настройку у пользователя,
иначе выполни задачу без OpenSpec. Ошибки декларации store покажи вместе с `fix`.
Если выбран store, найди его через `openspec store list --json` и сохраняй
`--store <id>` во всех поддерживающих его командах до конца операции.
Используй пути из JSON CLI, а не предположения о расположении файлов.
Если имя change не задано, используй однозначный контекст или единственный change;
при неоднозначности покажи `openspec list --json` и предложи выбрать.
Не придумывай игровые правила: неясности согласуй с владельцем до реализации.

1. Уточни цель и границы, если запрос неясен; получи имя в kebab-case.
   При совпадении с существующим change уточни продолжение или новое имя.
2. Выполни `openspec new change "<name>"`, затем
   `openspec status --change "<name>" --json`.
3. Построй полный набор артефактов из `applyRequires` и транзитивных зависимостей
   `requires`, включая зависимости уже существующих артефактов.
4. Для каждого недостающего артефакта в порядке зависимостей получи
   `openspec instructions <artifact-id> --change "<name>" --json`.
   Перечитай зависимости с диска. Следуй `instruction`, `template`, `context`,
   `rules`; если инструкция делегирует другому skill, используй его.
   Пиши по `resolvedOutputPath`; для glob выбери конкретный путь по инструкции.
   Не копируй context/rules в документ. Не создавай артефакты со статусом skipped.
   Пропускай условный артефакт только если это явно разрешает его instruction.
5. После каждой записи проверяй наличие файла и обновляй status. Само наличие
   tasks не доказывает наличие зависимостей. Заверши весь требуемый набор.
6. Покажи итоговый status, пути и назначение документов, причины пропусков.
   Предложи `$openspec-apply-change`; автоматически реализацию не начинай.
