# combat-rhythm: задачи после review

**Статус:** G1–G6 утверждены владельцем в рекомендованном варианте по прямому указанию в текущей сессии; planning готов к финальному ревью PR #23. Ни одна implementation-задача не выполнена. Согласование G1–G6 завершено; остаются финальное архитектурное ревью и отдельный запуск implementation. Наличие tasks и CLI-статус planning complete не разрешают начинать реализацию. Проверяемые трассы W/D/C и ожидаемые состояния — в [design.md](design.md); поведение — в delta-specs `tactical-attack` и `tactical-movement`.

## 1. Утверждённые решения и финальное ревью архитектуры

- [x] 1.1 Зафиксировано утверждение владельцем G1–G6 в рекомендованном варианте: preparation 1 / attack event 0 / recovery 3, актуальная соседность и LOS, начальная подготовка, сохранение цикла вне зоны, приоритет событий и HUD. Цикл только текущего прототипного существа; 1/0/3 — временные параметры баланса. Шаг 1, удар 2, HP 4/2 и урон 1 сохранены. Альтернатива с фиксированной клеткой не выбрана; прогноз HUD использует те же доменные правила, что исполнение; W/D/C обязательны.
- [ ] 1.2 Завершить финальное архитектурное ревью PR #23: `WorldSceneState` владеет immutable bite state, domain рассчитывает результат и preview без libGDX, публикация едина, core только отображает; отсутствуют общий scheduler и новый AI engine. При изменении решений пересогласовать design, delta-specs и tasks **до** кода.
- [ ] 1.3 После финального ревью подготовить отдельную implementation ветку/PR с привязкой к `combat-rhythm`; разрешение реализации получить отдельным запросом, не считать текущую planning-задачу таким разрешением.

## 2. Доменное состояние и начальные условия

- [ ] 2.1 Добавить Java 8 value состояния текущего прототипного укуса: READY/0, PREPARING/1, RECOVERING/1..3; состояние отсутствует вне tactical и после смерти существа. Проверить допустимые значения и независимость возвращённых snapshots.
- [ ] 2.2 Включить инициализацию цикла в подготовку успешного `enterTactical`: соседство с LOS → P1, иначе READY, без расхода времени; покрыть manual/automatic entry, отсутствие alerted, отказ и ALREADY_TACTICAL без сброса.

## 3. Resolver и результат

- [ ] 3.1 Заменить укус на каждой единице узким циклом фаз для принятых шага/атаки. Сохранить полную длительность новой фазы, продвижение только за принятые действия и тот же frozen perception/патруль. Проверить уход, промах/recovery, возврат, диагонального соседа, потерю LOS и дальнее READY без накопления укусов.
- [ ] 3.2 Зафиксировать порядок по design §4: HIT → отмена реакций при смерти существа → окончание фазы/укус → recovery → остановка при смерти охотника → новая подготовка. Проверить двухединичную атаку из R1, совпавшие HIT/BITE и lethal HIT, ранение без прерывания, lethal BITE на первой единице с duration=1.
- [ ] 3.3 Расширить существующий immutable `TacticalAttackResult`: bite before/after, ordered events с относительными сроками и фазовыми фактами; сохранить Outcome/HP/duration и согласованную проекцию BITE/HIT при её необходимости. Проверить порядок одинаковых offset и неизменность старого результата после следующей команды.
- [ ] 3.4 Подготовить все HP, placement, cycle, часы и result до публикации; сохранить последний принятый result при отказе. Snapshot tests: все причины отказа обеих команд, ошибка подготовки/переполнение часов, запросы в exploration, после смерти и после победы; нет частичного commit или восстановления occupancy умершего существа.
- [ ] 3.5 Добавить read-only preview допустимой атаки из того же внутреннего расчёта, что commit; не смешивать доступность с риском. Проверить неизменность сцены/lastResolution после повторов preview и равенство preview с фактическим результатом при неизменном исходном снимке, включая R1, lethal interruption и lethal HIT.

- [ ] 4.2 Покрыть всю W-трассу по командам и промежуточным единицам: победа 4/0 при t9 с дистанции 2 и при t8 с соседнего входа; R3→возврат→R2→полный удар, без бесплатных отказов или wait.
- [ ] 4.3 Покрыть D-трассу с полных 4/2 HP: 12 чередующихся соседних шагов, укусы t1/t5/t9, смертельный замах t13 с INTERRUPTED/duration=1. Из того же снимка t12 проверить безопасный отход и победу 1/0 при t20. Нельзя заменять полную трассу только fixture с искусственным 1 HP.
- [ ] 4.4 Покрыть C: две атаки подряд дают 3/0 HP и time=4; R1 пересекает конец recovery и подготовку, HIT/BITE на второй единице; HIT с поражением охотника отличается от INTERRUPTED. Проверить отсутствие фазовых событий после lethal HIT и будущих событий после lethal BITE.

Detection radius 3.0 world units, LOS и исходное размещение остаются прежними.

## 5. HUD и существующий ввод

- [ ] 5.1 Добавить постоянный текст и цвет текущей фазы/остатка без selection; подготовка объясняет все восемь соседей с LOS, recovery показывает оставшееся безопасное время, поражение имеет ясный исход. Все данные фаз поступают из domain. Проверить строки через небольшой test seam, не вычисляя правила в форматтере.
- [ ] 5.2 У кнопки «Атаковать · 2 ед.» отображать domain preview полного замаха: безопасно / ожидаемый урон / смертельное прерывание; недоступная атака сохраняет прежнюю причину отказа. Покрыть R1 с 2 HP и с 1 HP цели, а также P1 при 1 HP охотника.
- [ ] 5.3 Обновить `showResolution` на полный ordered event list: preparation, HIT, BITE, промах, recovery start/end и исход. Не трактовать каждый новый тип как BITE; сохранить последнюю строку после presentation и постоянную фазу независимо от неё.
- [ ] 5.4 Сохранить tap свободной соседней клетки, tap существа → release → кнопка, область ≥48×48, pointer 0, FitViewport/letterbox и lifecycle ресурсов. Организовать перенос/компактные строки предупреждения в viewport без перекрытия доступных controls, проверить portrait/landscape/resize.
- [ ] 5.5 Расширить существующие `TacticalAttackPointerTest`, `TacticalPointerTest` и transition tests: один busy gate, entry 220 / move 180 / attack 240 мс, нулевой первый кадр, конечный кадр, большие/NaN/отрицательные delta, hold/drag/multiple pointers, pause/hide и resize. Нет новых команд, смены selection, повторного damage или продвижения фаз во время presentation; только новое нажатие после завершения.
