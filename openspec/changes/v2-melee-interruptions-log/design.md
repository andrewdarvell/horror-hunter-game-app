## Context

См. proposal.md. WorldSceneState уже вычисляет один атомарный TacticalAttackResult и ждёт commandActive/hunterRecovery. ClashFacts содержит причинную timeline, HP после каждого факта, маршруты, состояния фаз и stopReason. FirstScreen запускает playback только после принятой команды; ручной Desktop fixture создаёт этот экран.

## Goals / Non-Goals

Исправить семантику отмены v2 и наблюдаемость ручного боя без изменения числового профиля и без второго боевого состояния. Не менять общий порядок пакетов HIT → контакт волка → окончания recovery → новый план.

## Decisions

- Исключение применяется только к обычному укусу v2, Kind.ATTACK и живому охотнику. Проверка летальности выполняется после ущерба, до терминальной остановки, поэтому смерть до дедлайна даёт явный ACTION_INTERRUPTED. Прыжок и прочие действия сохраняют прежнюю семантику.
- Существующие сроки и atBoundary сохраняются: после нелетального укуса commandActive не сбрасывается, поэтому ранний recovery не открывает решение. Повторный контакт на дедлайне может назначить новый recovery. Завершённый удар не отменяется задним числом.
- Formatter в core принимает только опубликованный результат и метаданные запуска, печатает ClashFacts в исходном порядке без сортировки и дублирования проекции events. Данные событий без ClashFacts выводятся из events. Он не хранит HP, часы или планы между командами.
- FirstScreen получает необязательный debug sink. Вызов только на путях принятой команды, перед playback (и после обычного движения); защита по identity последнего опубликованного результата исключает дубликаты. Preview и render не вызывают sink. Ручной fixture включает console sink; автоматический smoke может включить его для проверки полного примера через те же UI-команды.
- domain остаётся чистой Java; вывода и зависимости от logger в нём нет. Все причины и фазы читаются из TacticalAttackResult.

## Risks / Trade-offs

- Повторные укусы могут убить охотника до конца длинного действия → проверка смерти на первом и повторном укусе, сохранение терминального исхода.
- Общие отметки могут ошибочно открыть ввод или поменять приоритет → точные JUnit трассы и Desktop input gate smoke.
- Старый v2 smoke ожидает прерванный удар → обновить только зависящую от новой семантики трассу; ordinary/regression ожидания сохранить.
- Изменение не гарантирует победу серией обычных ударов при прежнем балансе; критерий — завершение удара живым охотником после нелетального укуса.

## Migration Plan

Отдельная ветка/PR. Числовой конфигурации и миграции данных нет. Change не синхронизируется в main specs и не архивируется до приёмки. Семантика уточняет активный boar-spear-wolf-clash; его текст о безусловном прерывании укуса приводится к согласованному исключению.
