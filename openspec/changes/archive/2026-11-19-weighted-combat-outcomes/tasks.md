## 1. Значения и snapshots

- [x] 1.1 Создать `WeightedOutcome` в новом пакете `domain.combat.outcome` по P1. Готово, когда JUnit 5 в `OutcomeTableTest` проверяет value equality, допустимые id/веса, канонизацию -0.0 и IllegalArgumentException для null/пустого/с пробелами по краям id, отрицательных/NaN/бесконечных весов.
- [x] 1.2 Создать `OutcomeTable.of/getOutcomes` с defensive copy и сохранением порядка. Готово, когда тесты подтверждают уникальность id, запрет null-коллекции/элементов, чувствительность id к регистру, неизменяемость snapshots и возможность пустой/нулевой промежуточной таблицы.

## 2. Явная подготовка исходов

- [x] 2.1 Добавить `add/remove/replace` без builder и registry. Готово, когда тест [a:50,b:30,c:20] → add d:10 → remove b → replace c на e:40 даёт [a:50,e:40,d:10], проверены конфликты, отсутствующие id, replace с прежним id, исходный snapshot не меняется.
- [x] 2.2 Добавить `filter(Predicate<String>)` и `withWeight`. Готово, когда фильтр сохраняет порядок, отсутствующий id нельзя восстановить изменением веса, null predicate и невалидные веса отклоняются, исключение predicate распространяется без изменения исходной таблицы, повторное назначение веса даёт последнее значение.
- [x] 2.3 Добавить pure fixtures по P2, без игровых классов и новых статусов. Готово, когда тесты показывают добавление/замену → физический фильтр → изменение весов, запрет добавленного физически невозможного варианта, [50,30,20] → [25,30,45] и повторную фильтрацию после изменения состава. Ни один fixture не утверждает коэффициенты игрового баланса.

## 3. Разрешение и численный контракт

- [x] 3.1 Создать stateless `WeightedOutcomeResolver.resolve(OutcomeTable, DoubleSupplier)` с точными десятичными суммами/произведением по P3, без деления и дополнительных зависимостей. Готово, когда `WeightedOutcomeResolverTest` детерминированно достигает каждого исхода таблиц 1/2/3/5 и проверяет нормализацию/инвариантность точного масштабирования на 2.
- [x] 3.2 Закрепить полуоткрытые интервалы. Готово, когда для 50/30/20 проверены 0, границы 0.5/0.8, ближайшие представимые значения с обеих сторон и Math.nextDown(1.0); leading/interior/trailing zero weights никогда не выбираются.
- [x] 3.3 Проверить численные крайние случаи и ошибки. Готово, когда равные пары MAX_VALUE/MIN_VALUE делятся на границе 0.5 без overflow/underflow, пустой/нулевой финальный набор и null table/source отклоняются до RNG. Тест канонической десятичной семантики использует [0.1,0.2,0.7] с границей 0.3; значение `0.1 + 0.2` не должно автоматически округляться обратно к 0.3.

## 4. Случайность, воспроизведение и граница API

- [x] 4.1 Добавить counting/failing supplier fixtures. Готово, когда подготовка потребляет ноль отсчётов, единственный положительный вес (в том числе среди нулевых) — ноль, несколько положительных — ровно один; -0.0 допустим как 0; -0.1, 1, NaN, ±Infinity отклоняются после одного вызова; исключение supplier распространяется без повторной попытки.
- [x] 4.2 Проверить воспроизводимость по P4/P6. Готово, когда два независимых Random с одним фиксированным seed дают одинаковые последовательности id и счётчики на серии одинаковых таблиц с singleton-случаями; перестановка списка явно меняет интервалы, а порядок HashMap не участвует.
- [x] 4.3 Добавить ограниченные property-like циклы без новой библиотеки. Готово, когда для небольших положительных целых весов и фиксированной сетки u всегда выбран существующий положительный разрешённый id, точное масштабирование на 2 сохраняет результат, исключённые id никогда не возвращаются. Статистических flaky-порогов нет.
- [x] 4.4 Продемонстрировать внешнее потребление id обычной тестовой таблицей описаний по P5. Готово, когда тест работает без WorldSceneState, libGDX, конкретного волка и оружия; resolver не исполняет эффекты и возвращает только String.
