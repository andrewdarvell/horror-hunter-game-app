## Context

Статус: **R1–R6 утверждены владельцем проекта в предложенном варианте; planning подготовлен для финального ревью PR #20**. Основание — явное решение владельца в текущем обсуждении. Повторное согласование R1–R6 не требуется. Все числовые параметры остаются временным балансом/настройками прототипа, а не окончательными значениями игры. Реализация не начата и ожидает отдельного запроса.

Изучены proposal.md, актуальные domain/core и принятые specs; источник направления — соседний репозиторий `horror-hunter-game-design/docs/game-design/exploration-and-combat.md`, разделы 2–5 и 7, и ADR-001. Локальный design-документ использован непосредственно, его таблица длительностей не считается балансом.

Текущее состояние:

- `WorldSceneState` владеет копиями HunterState/CreaturePatrolState; `update` в tactical возвращается до движения, патруля и detection. Игровых часов, HP и атак пока нет.
- `tryMoveHunterTo` атомарно назначает клетку и центр; восемь соседей, статический полный путь круга. `TacticalPlacement` требует ровно две разные клетки. Состояние патруля и lastSeen копируются и сохраняются.
- `WorldGeometry.hasLineOfSight` блокирует пересечение **и касание** замкнутого AABB. Путь круга для перемещения допускает касание без проникновения. Эти разные контракты нельзя смешивать.
- `FirstScreen` обрабатывает основной pointer через InputAdapter, выбирает клетку TacticalCellPicker и выполняет шаг на touchDown. Удержание отсечено primaryDown. FitViewport отсеивает поля до unproject.
- `TacticalEntryTransition` уже поддерживает 220 мс входа и 180 мс шага с нулевым первым кадром; это исключительно представление. В core уже есть JUnit и тесты pointer/transition, вопреки устаревшему описанию в AGENTS.md.

## Goals / Non-Goals

**Goals:** один полностью наблюдаемый цикл «намерение → автоматическое разрешение длительности и реакции → показ результата → новая команда», работающий без graphics в domain и одинаковый для mouse/touch. Все связанные изменения занятости и поражения публикуются атомарно.

**Non-Goals:** общий combat engine, очередь намерений, initiative scheduler, event bus, AP, инвентарь, несколько целей, преследование, полный radial UI, выход из tactical, сохранения, глобальная симуляция событий за кадром. Счётчик tactical-времени — ограниченная основа для будущих общих часов; exploration ещё не тарифицирует тайлы, конверсия в минуты леса и offscreen AI остаются отдельным срезом. Это не завершённая реализация всей модели времени дизайн-документа.

## Decisions

### Сценарий целиком

Игрок завершает вход в tactical, тапает клетку живого существа: появляется выделение и компактная кнопка «Атаковать · 2 ед.», подсказка «укус каждый 1 ед.; возможное прерывание». Новый tap/click по кнопке проверяет актуальную цель в domain. Отказ показывает причину без расхода времени. Принятая атака за один вызов разрешает до двух условных единиц: на первой живое существо кусает доступного охотника, на второй сначала завершается удар, затем выжившее существо может укусить снова. Если охотник повержен раньше, оставшийся удар отменяется и время останавливается на фактической единице поражения. Никаких ручных ожиданий.

Core показывает краткий упорядоченный результат, не проигрывая симуляцию заново. После конечного кадра и нового нажатия можно снова выбрать действие либо тапнуть свободную соседнюю клетку для шага. После поражения существа его клетка свободна, тело остаётся отметкой, tactical сохраняется. После поражения охотника показан результат, команды заблокированы, автоматического рестарта нет.

Swept weapon shape точнее моделирует толщину оружия, но требует нового геометрического правила; полный путь тела из движения избыточно запрещает удары. |

Все шесть решений таблицы утверждены в указанном варианте; альтернативы сохранены как обоснование выбора. Уточнение R2: укус раз в условную единицу — поведение только текущего прототипного существа, а не универсальное правило будущих врагов. Общий принцип автоматического разрешения действий разной длительности сохраняется; частота, длительности и реакции будущих врагов будут определяться отдельно. Не вводить универсальный enemy tick/attack policy или систему типов врагов ради этого уточнения. Декоративные цвета/расположение текста можно уточнить позднее без изменения контрактов.

### Минимальное разрешение времени

В domain добавить scene-owned целочисленный счётчик `tacticalTimeUnits`, изначально 0, и небольшой закрытый resolver для двух известных действий. Не вводить универсальную иерархию действий: атака и движение остаются явными методами. Профиль содержит только фиксированные длительности/урон/начальные HP; не настраивается игроком, длительность не принимается из UI.

1. Валидировать намерение целиком без мутаций. Отказы не меняют HP, время, placement, патруль, perception.
2. Подготовить копию состояния. Атака держит цель неподвижной до срока 2; движение назначает новый центр в срок 1.
3. За один синхронный вызов пройти целые единицы до срока действия: завершить эффект охотника на его сроке, затем проверить возможность одного укуса текущего прототипного существа на этой границе. Для атаки до срока сначала доступны только реакции. Укус использует ту же соседность/LOS. Пропущенный вне дальности укус не копится; преследования нет.
4. Перед каждым эффектом проверить, что участники ещё живы. Летальный укус прекращает действие немедленно. Обычный урон не прерывает удар. Летальный удар убирает будущие укусы; остаток уже принятого действия до его срока оплачивается, при поражении цели на сроке удара это ровно 2 единицы.
5. Вместе опубликовать HP, фактическое время, позиции и occupancy; вернуть результат с последовательностью фактов. Это маленький список значений для представления и тестов, не event bus.

Для утверждённого временного профиля прототипа: первая атака даёт укус t+1, удар t+2, укус t+2: HP охотника 2, существа 1. Вторая: укус t+1, летальный удар t+2, без ответного укуса: HP охотника 1. В тесте с 1 HP охотник погибает на первой единице, удар не происходит, потрачена 1, а не 2. Шаг из соседства сначала меняет центр, затем проверяет укус из новой позиции; это сознательно упрощает фазу движения, не моделирует opportunity attack.

`update` остаётся замороженным в tactical. Не вызывать `advancePatrol(duration)` и не переводить duration в render delta: это возобновило бы exploration-процессы. Выбор цели, отказ, вход, кадры и resize не двигают счётчик. После поражения цели дальнейшие шаги продолжают стоить 1, без укусов. После поражения охотника все новые действия отклоняются без времени.

### Границы domain/core и контракты

- `domain.actor`: минимальное HP/life state, копируемое вместе с участниками. Не выводить life state из цвета или наличия placement. CreaturePatrolState продолжает хранить frozen патруль и perception; HP не сбрасываются при копировании/withTacticalPosition.
- `domain.tactical`: конкретный immutable `TacticalAttackResult`: acceptance/refusal (NOT_TACTICAL, INVALID_TARGET, TARGET_DEFEATED, HUNTER_DEFEATED, OUT_OF_RANGE, BLOCKED), resolution (HIT либо INTERRUPTED), фактическая длительность, HP before/after, фактический damage каждого эффекта, поражение и упорядоченные факты. В утверждённом прототипе MISS недостижим; RNG не вводится. Принятость не равна попаданию: прерванная атака принята, но урона не наносит.
- `WorldSceneState.tryAttackCreature(...)` принимает идентификацию единственной цели (например ожидаемую creature cell), сверяет её с текущей; не атакует произвольный переданный actor. Read-only проверка доступности для UI и исполнение используют одинаковое правило, исполнение всегда перепроверяет.
- Сохранить `tryMoveHunterTo` и его различимые геометрические отказы; для его успеха нужен результат разрешения с HP/временем/реакцией (расширить value result либо добавить конкретный подробный результат и делегирующий совместимый метод). Один вызов на шаг, без повторного применения. Добавить отказ HUNTER_DEFEATED.
- `core`: выбор цели, context UI, маршрутизация pointer, busy, показ результатов и прежние transitions. Никаких HP-правил или RNG в рендере. Desktop/Android используют один InputAdapter; новых dependencies и внешних портов не требуется. Java 8, без records.

### Геометрия атаки

Разность клеток считать через long; `max(abs(dx), abs(dy)) == 1` — единственное правило дальности. В одной клетке атака невозможна. Ортогональ имеет центр на 1 размере клетки, диагональ — sqrt(2); отдельный евклидов порог в 1 клетку не применять. Ни радиус обнаружения, ни сумма радиусов тел не определяют дистанцию удара.

Затем `hasLineOfSight(hunterCenter, creatureCenter)` на общей геометрии: тонкая стена и точное касание угла блокируют удар. Свободная диагональ разрешена даже при непроходимом полном пути круга охотника: оружие прототипно считается линией нулевой толщины. Проверки свободных центров двух ортогональных соседей не нужны. Участники при атаке не смещаются. Для укуса то же правило в обратном направлении.

### Поражение, placement и perception

Явно расширить TacticalPlacement двумя допустимыми состояниями: охотник + живое существо в разных клетках; охотник без creature occupant. Предпочтительно factory `withCreature(...)`/`hunterOnly(...)` и Optional доступа к creature cell. Не разрешать произвольный null в существующем конструкторе и не оставлять фиктивную занятую клетку. Обновить все потребители и тесты.

При поражении существа atomically убрать только occupant; последнее world position остаётся для отметки тела. Охотник может затем занять этот центр без пересечения **занятых** клеток; совпадение с позицией отметки допустимо. По телу атака отклоняется, context action не открывается. lastSeen и alerted сохраняются как историческое frozen состояние; указатель и контур occupancy существа скрыты при поражении. Патруль не возобновляется. Живое существо при атаке не получает автоматического detection/обновления lastSeen: прототипный ответ задаётся самим resolver независимо от alerted, даже после ручного входа. Это реакция на принятое действие, не новый AI восприятия.

Поражённый охотник остаётся occupant своей клетки; шаг/атака недоступны. `SceneMode` остаётся TACTICAL при обоих исходах, повторный T ничего не перестраивает. Отдельный GameOver/выход/рестарт не добавляется.

### Mouse/touch и визуальные блокировки

Приоритет обработки нового основного нажатия: busy → игнорировать; context button → только попытка атаки; карта → живая creature cell выбирает цель, свободная клетка закрывает context и выполняет прежнюю попытку шага. Далёкое существо можно выбрать, кнопка сообщает причину недоступности. Нажатие вне игровой viewport-области игнорируется. HUD внутри этой области проверяется в логических screen-единицах до world unproject и не пропускает событие в карту. Resize пересчитывает bounds HUD, не domain.

После выбора цели для атаки требуется отпускание и **новое** нажатие; событие открытия меню не может активировать появившуюся кнопку. Дополнительные pointers, drag, удержание не создают действий. Escape и tap по выбранному существу закрывают context; tap свободной клетки одновременно закрывает его и сохраняет прямое движение. В exploration прежние WASD/T/патруль/LOS сохраняются.

Busy общий для entry, move и показа атаки. Синхронное разрешение и установка busy выполняются в одном обработчике до следующего события; новая команда не накапливается. Для шага прежняя анимация 180 мс остаётся единственной блокировкой, а результат укуса отображается вместе с ней; если укус поверг охотника, шаг всё равно уже завершён в центре. Для атаки отдельный presentation timer 240 мс с нулевым первым кадром, endpoint clamp и safe delta, без изменения координат. Плашка показывает порядок «укус → удар → укус»/«удар прерван» и HP; краткая вспышка лишь дополняет текст. HP-панель результата использует snapshots, domain уже имеет финальное состояние. После поражения цели нельзя до конца показа занять её освобождённую клетку через UI.

Не менять TacticalEntryTransition и его два режима ради атаки. Сохраняются 220/180 мс, нулевой первый кадр, камера по visualHunterPosition, точное завершение и resize. Busy снимается после показанного конечного кадра; новый ввод требует нового нажатия. hide/pause закрывают context и сбрасывают pointer latch; потеря focus не должна оставлять кнопку зажатой. Dispose освобождает добавленные UI-ресурсы и восстанавливает input processor по существующему правилу.

## Risks / Trade-offs

- [Реакция на шаг меняет прежний контракт] → отдельная delta tactical-movement: состояние патруля/perception остаётся прежним, HP и tactical clock теперь меняются. Нельзя просто сохранить старое утверждение «весь снимок неизменен при успехе».
- [Детерминизм и приоритет охотника дают искусственный ритм] → R1–R3 утверждены для прототипа; числовые параметры временные, playtest не выдаётся за окончательный баланс.
- [HP охотника расширяет срез] → только HP, поражение и блокировка команд; без death screen/сохранений/сложного AI. Отказ от укуса потребует пересмотра R2, а не молчаливого удаления реакции.
- [Часы пока только tactical] → не утверждать наличие глобальных world events; интеграция exploration/offscreen времени — будущий срез.
- [Длинный кадр/повтор pointer дублирует эффект] → domain рассчитывается один раз, последующие кадры читают immutable result; тесты пакета событий и конечного кадра.
- [Поверженная цель ломает существующие dereference placement] → проверить все вызовы getCreatureCell, занятость, picker, drawOccupiedCell и lastSeen arrow, включая движение в клетку тела.

## Migration Plan

R1–R6 утверждены и отражены в planning. Следующий шаг — финальное ревью PR #20; implementation начинается только по отдельному запросу, без повторного согласования R1–R6. Сначала domain и тесты, затем pointer/UI и regression suite. Нет миграции сохранений или данных; текущая сцена создаётся заново. Откат — тематический revert реализации целиком, включая изменения placement и контрактов. Актуальные `openspec/specs` не менять до приёмки; sync/archive только отдельным шагом после реализации и ревью.
