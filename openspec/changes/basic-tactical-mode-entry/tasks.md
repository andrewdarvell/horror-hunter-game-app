## 1. Доменная модель и безопасная расстановка

- [ ] 1.1 Добавить режим exploration/tactical, неизменяемую расстановку двух различных клеток и различимые исходы попытки по [design.md](design.md), сохранив единственные текущие позиции участников и существующую фиксированную сетку.
- [ ] 1.2 Реализовать чистый расчёт кандидатов: валидация снимка, проверка диапазона до worldToCell, смещения индексов через long, конечность и обратное преобразование центров; область строго 3×3 для каждого участника.
- [ ] 1.3 Для каждого кандидата проверять isCellPassable и полный isCirclePathValid из исходной позиции с собственным радиусом; не использовать LOS, скольжение или поиск обхода вместо проверки пути.
- [ ] 1.4 Реализовать совместный перебор не более 81 пары и порядок выбора: сохранённые исходные клетки, сумма смещений, смещение охотника, координаты; обеспечить независимость от порядка перечисления и конечность оценки.
- [ ] 1.5 Реализовать единое применение подготовленного плана внутри доменного агрегата; исключить частичную запись позиций, клеток или режима и сохранить метаданные патруля, alerted и last-seen.

## 2. Доменная координация перехода

- [ ] 2.1 Разделить проверку обнаружения и продвижение патруля, сохранив прежний update как композицию для существующих вызовов и тестов; валидацию выполнять до изменения состояния.
- [ ] 2.2 Реализовать порядок exploration: движение охотника → одна проверка обнаружения → одна попытка по фронту обнаружения или ручному запросу → патруль только при сохранении exploration и отсутствии настороженности; сохранить проверку при нулевом интервале.
- [ ] 2.3 Реализовать заморозку обоих участников и восприятия после успеха, отсутствие автоматических повторов после отказа, новую попытку по ручному запросу и идемпотентный вход в tactical.

## 3. Доменные тесты и регрессии

- [ ] 3.1 Добавить JUnit-тесты обычного размещения, точных центров, границ и отрицательных координат; проверять две сохранённые различные клетки и соответствие обеих фактических позиций их центрам.
- [ ] 3.2 Добавить тесты безопасной исходной позиции при заблокированном центре, безопасных endpoints по разные стороны тонкого AABB внутри исходной клетки и у альтернативного центра, блокировки пути радиусом, допустимого касания и нулевого смещения.
- [ ] 3.3 Добавить тесты общей исходной клетки, разных радиусов, локальной альтернативы и жадного тупика «охотнику A/B, существу только A»; проверять фактическую ожидаемую пару.
- [ ] 3.4 Проверить каждый приоритет выбора и разрешение равенств, повторяемость и перестановку перечисления кандидатов; проверить отказ при наличии подходящих клеток только вне области 3×3.
- [ ] 3.5 Проверить отсутствие кандидатов одного участника и единственную общую доступную клетку; сравнить полное состояние до и после отказа, включая обе позиции, placement, mode и метаданные патруля.
- [ ] 3.6 Проверить отсутствующие данные, NaN/Infinity, неположительные радиусы, недопустимую исходную геометрию, выход исходной клетки за int, соседей около обоих пределов int и непредставимые центры; различать ошибку входа и отсутствие пары без частичного применения.
- [ ] 3.7 Проверить координацию успешного и неудачного автоматического входа, ручного входа до обнаружения и после отказа, совпадения триггеров и повторного входа; проверить отсутствие автоматических повторов и сохранение движения/обнаружения, выполненных до неудачной попытки.
- [ ] 3.8 Проверить успешный вход при нулевом интервале и заморозку позиций, клеток, alerted, last-seen, waypoint, направления и времени патруля при дальнейших нулевых и больших обновлениях tactical; last-seen должен сохранять позицию до snap.
- [ ] 3.9 Выполнить существующие тесты свободной навигации, геометрии, patrol и detection; при изменении ожиданий ограничить их согласованными deltas и сохранить прежние проверки exploration.
